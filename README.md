# Not Mario’s World

An original desktop pixel platformer for Game Day Thursday. One host runs a room for up to 25 players. Each player has a separate, identical copy of the configured race levels. The active catalog contains Whimsical Woods and Troubled Tides, giving the default route **Lobby → Forest → Tide → Podium**. Inferno Express is disabled; its generator and assets are retained. Additional catalog levels remain supported.

## Run locally

Install Node.js 22 or later, then from this directory:

```sh
npm ci
npm start
```

Open [http://localhost:10000](http://localhost:10000). There is no frontend build step. `PORT` overrides the default port. Run `npm test` for the physics/scoring and real WebSocket integration checks.

For local editing, use `npm run dev` so Node restarts when shared game rules change. Refresh the browser after changes. The browser checks `/health` before joining and displays a clear restart message if the server is still using older rules. Server restarts clear test rooms.

## Local level companion

Run `npm run editor` and open [http://127.0.0.1:10001](http://127.0.0.1:10001). The separate local browser editor starts with a blank forest level, supports asset placement and timer/animation previews, and exports versioned level JSON with separate asset, reusable-definition, and placement layers. Import an atlas image and review its cuts, geometry and optional metadata before adding assets to the drawer; no schema is required. The bundled forest's missing geometry is marked as editable estimates. Atlas cuts support polygon outlines: double-click an edge to add a point, then drag points to hide unwanted neighboring pixels without editing the atlas image or collision shapes. See [the companion guide](tools/level-editor/README.md) for controls, the export contract, and limitations. Drafts stay in tool storage until you export and replace a configured JSON. The editor, viewer and live JSON levels share rendering and collision code.

The loading screen shows the four avatars jumping together inside a circular pixel-card panel while level data and artwork load. It respects reduced-motion preferences and opens the game as soon as loading finishes.

Scene changes use a cartoon iris wipe inside the game viewport. A circular window closes inward to pure black, the scene changes under that cover, and the circle opens to reveal the new world, including its corners. Each direction takes 500 ms by default. Controls are blocked during the wipe; the shared round clock keeps running, and existing victory-stinger pauses still apply.

Developers can change `SCENE_TRANSITION_DURATION` in `public/app.js` (milliseconds per direction). The reusable `IrisTransition` controller in `public/game/iris-transition.js` also accepts `{ duration }` and exposes `setDuration(ms)` and `run(changeScene)`; scene callbacks execute beneath the full-black cover.

The Waiting Woods is a safe practice lobby among detailed pixel-art trees and overgrown ruins: mossy arches, broken columns and walls, and woodland plants. Leaves drift in the breeze with gentle tree sway and friendly wildlife; reduced-motion preferences keep the scenery still. Explore the in-world hint boards while the host prepares the race. Move with **A/D** or **left/right arrows**; jump with **Space**, **W** or **up arrow**, releasing the key before jumping again. The host starts the race for everyone. In the race, collected coins survive death, reached checkpoint flags save distance and respawn position, exits bank a world's score, and **F / USE** activates a held chest power. Open the **!** help panel for the full rules and the trophy panel for live standings.

## JSON levels

Race backdrops have camera parallax for a sense of depth: decorative background artwork moves at 12% of horizontal camera speed, like the lobby's distant scenery, while platforms and game props move at full speed. Forest and tides use their existing authored background strips, with no artwork or placement changes. The playable JSON viewer shows the same effect as the live race; the placement editor keeps its world-space layout for accurate selection and editing. Gameplay-bearing or colliding artwork stays aligned with the course. The disabled Inferno course retains its layered parallax code for later restoration.

Authored props share cosmetic VFX across the companion, viewer and live race: coin sparkles, hazard particles, checkpoint beams and reached-banner colors, moving-platform motes, warning blinks and disappearance effects, and beam/exit glow. Configure hazard categories and beam/portal colors in **Prop VFX**, and localized mist pockets in the companion's **Atmosphere** tab. Newly enabled vanishing platforms default to a three-second warning; existing level timings remain authored. See the [companion guide](tools/level-editor/README.md#prop-vfx-and-atmosphere) for controls and export settings.

Beams blink along their path for the final **0.5 seconds before firing**, giving you a brief warning. The highlight is harmless; the authored firing schedule and damage timing stay the same. It follows start delays, phase offsets and respawn resets, and uses the beam's existing Prop VFX enable/color settings.

The live forest loads the compact game export [WhimsicalForest.json](public/assets/sprites/forest/tileset/WhimsicalForest.json). Keep its editable source in `tools/level-editor/levels/WhimsicalForest.json`; **Export editor JSON** keeps embedded artwork and authoring metadata, while **Export game JSON** keeps runtime data and references existing project images. Regenerate it with `npm run export:game -- tools/level-editor/levels/WhimsicalForest.json public/assets/sprites/forest/tileset/WhimsicalForest.json`. Its 344 placements define the artwork, collision shapes, motion, hazards, 91 coins, two checkpoints, selected spawn, exit, three power chests, three decoy chests and 12 creature/shooter placements. The game export preserves those authored placements without filling in objects from the old forest. Tide (level 2) loads [TroubleTides.json](public/assets/sprites/tide/tileset/TroubleTides.json), preserving its authored 6000×600 world, 48 coins, two checkpoints, selected spawn, exit, three power chests and three decoy chests. Its editable source remains in `tools/level-editor/levels/TroubleTides.json`. Inferno is excluded from the active catalog; its compatibility course remains in source.

Register each level in [level-catalog.json](public/game/level-catalog.json):

```json
{ "id": 4, "name": "Another woodland", "theme": "forest", "src": "/assets/sprites/another/tileset/AnotherLevel.json" }
```

Add that object to the catalog's `levels` array. Use a unique positive integer ID; 0 belongs to the lobby, and the podium is separate. Each entry's `src` loads its own exported v2 level document. Paths may be root-relative or relative to the catalog; atlas image paths are relative to their level JSON, and embedded images work too. Inferno is currently disabled. Restoring it would require adding its ID 3 entry back to the catalog, with `legacy: true` for the retained course or a JSON `src` for an authored replacement. Keep IDs stable. The catalog order becomes the default race order, and hosts can reorder all entries in Game settings. There is no three-level limit or renderer edit needed to add a level.

`theme` selects the existing audio identity (`forest`, `ocean`, or `hell`); renderer geometry and artwork do not branch on that value. Reusing a theme across several levels is supported. Configure gameplay through the editor's explicit roles: coin, ordered checkpoint, spawnpoint, exit, power chest, or decoy chest. Artwork kind alone does not grant a gameplay role. Levels end by touching their authored exit trigger.

After editing the catalog or a level JSON, restart the game server and refresh player/host tabs. Invalid documents and missing files fail visibly instead of falling back to a different course. The source forest JSON is kept unchanged by renderer integration.

The game loads lossless `.compressed.webp` artwork copies while retaining the original PNGs. **Export game JSON** in the editor and `npm run export:game` automatically prefer an existing compressed sibling of each matched project PNG; images without a compressed copy keep their original path. **Export editor JSON** retains the original sources for authoring. Regenerate compressed copies after changing their source artwork.

## Host a game

1. Click **Host a game** in the homepage header to create a room immediately, or choose **Host a room → Create a game room**.
2. Copy the room code or invite link and send it to the team. The host is separate from the 25 player slots.
3. Open **Game settings**. Choose the **World order** using the stage selectors (choosing a world swaps its position), then set a 1–60 minute round, scoring weights, separate power/attack/defense durations (1–60 seconds each), and power strengths. Set targeted attack cost (1–1000 coins, default **30**) and cooldown per player (1–3600 seconds, default **60**). Defaults are 15 minutes, 10 points per coin, and 1 point per 32-pixel tile reached.
4. Five default icebreakers are included, including the executive dashboard and pillows/blankets questions. Edit or remove any in settings; at most five are allowed, each with exactly two choices. **Launch** each question manually. It appears as a pixel broadcast inside every player's game viewport and the host's world broadcast stage. Players click a choice or press **1 / 2**. Everyone sees named votes live; voting closes after 15 seconds. Use the in-world **Skip question** or **Dismiss question** control to clear it. Questions run in the lobby.
5. Players join directly into the playable lobby and can move and jump immediately. At the upper-left of the game viewport, they can edit their name, choose one of four circular avatar portraits, and click the color swatches below them. Appearance changes apply immediately while they practice. A compact progress card shows the progress bar, world number, and respawn count in the upper-right during both lobby and race, including fullscreen, without a displayed name or sidebar profile card. Progress and avatar selection use the same pixel frames and monospace text as broadcast messages. Score and progress stay fixed when broadcasts appear beside the power card; the final countdown sits at the lower-right while progress stays upper-right; powers remain upper-left during the race.
The player game screen fits the available browser width and remaining height, preserving 16:9 and keeping the entire game visible without page scrolling. The adventure heading is compacted into the existing site header, freeing room above the game without increasing header height. The player lobby/race header keeps only the brand icon; entry and host branding remain unchanged. Total score appears inside the game, immediately left of progress, with matching pixel styling. The three stat cards below the game are removed. Character selection, score, progress, instructions/leaderboard, and power overlay cards use a 56.25% scale relative to the original design (two successive 25% reductions). Power labels use sharp HTML text in the same font as Total score, while their frames remain pixel artwork. The power slot and active-effect cards match the progress/score panels’ dark green fill, lime pixel frame, flat shadow, and monospace text. The power slot shows a left-aligned power name and [F] activation button without an icon; queued/testing states remain visible. All broadcasts and game-world popups—including attack/defend banners, icebreakers, final countdown, quiz/answer cards, chest choices, death/respawn and finish panels—now share that scale, pixel frames and crisp monospace HTML lettering. During play, broadcast banners sit directly beside the power card on its right, aligned to the same top edge. On the host dashboard, active broadcasts instead fill the Shared Announcements section with large text; that stage uses its full available width and full-size cards for readability. Total score and world progress stay at their upper-right anchors when these banners appear. Death keeps its red border/dark background; countdown retains its gold accents. Full-screen shading stays full-screen. The final 10-second timer sits at the lower-right, including fullscreen, without moving score or progress from the upper-right. The timer and lobby icebreaker use crisp HTML lettering while retaining their original colors and pixel card artwork. The death-cause panel also uses crisp text and a separate respawn-countdown line, with a red pixel frame and its original dark body background, centered horizontally and slightly above the game viewport’s vertical midpoint. Overlay text retains readable sizes independently of the compact panels. Scoring rates sit immediately left of the timer at their original font size; the bottom coin/checkpoint/exit note is removed.

6. Choose **Start the race**. Players enter the first world in your selected sequence together, and their name, avatar, and color lock for the race. New arrivals enter immediately with only the remaining room time. Instructions and the live leaderboard appear as pixel panels inside the game viewport (also in fullscreen). They default to collapsed pixel **!** and **trophy** icons in both lobby and race; click an icon or activate it with the keyboard to open/close its scrollable panel. They hide while an icebreaker or unanswered power question needs your attention.
7. Follow the lightweight player progress dashboard: current world/stage, progress/checkpoint, score, banked points, coins, deaths, connection status, and last update. Each player card also shows a frozen miniature of their world at their last reported X/Y location, with the snapshot update time. Thumbnails refresh only with existing gameplay events, so they can remain unchanged while the player moves between reports. They show baseline artwork rather than synchronized collected coins, defeated enemies or triggered platforms. The host browser draws the thumbnails using shared artwork; Render relays small location fields, without rendering images or running extra player simulations. A new lobby run sends one initial location snapshot; lobby movement alone does not refresh it. Collapsing Run reports defers thumbnail rendering until reopened. Collapse **Run reports** whenever you want more room for shared announcements. The separate announcement stage shows icebreakers, messages, power phases, and the final countdown on a plain background, without a game-world scene. During play, use **Host challenges** to choose a power and challenge all active players to defend.
8. A visible, audible countdown runs during the **final 10 seconds of play**. Players can still move, collect coins, and score. At zero, gameplay stops and everyone teleports into **the separate podium ceremony in the castle's courtyard ruins**. Detailed pixel-art arches, broken columns, overgrown walls and a flagstone terrace frame the weathered stone stands, with gentle wind and celebratory effects that respect reduced-motion preferences. The three main podium bases reach the courtyard floor, with clear space below the champions banner for the winner's name and crown. The champions/finalizing banner and place/points labels match the broadcast cards' dark-green fill, lime pixel frames and flat shadows. **Finalizing scores…** can appear for up to **2 seconds** while final reports arrive; this adds no playtime. Then the top three appear on the main podium and every remaining player on a ranked stand. Your own avatar and rank are highlighted. The podium also celebrates **Respawn Royalty** for the most deaths and **Coin Goblin** for the most coins collected across the run, including coins spent on attacks. Ties share the title; zero totals show a neutral message. These callouts do not change scores or ranks. Review full rankings, download a CSV, or return everyone to the lobby. Manual **End round** uses the same cutoff and finalization flow.

The host can refresh and resume using the host credential kept in that tab’s session storage. Keep the host tab open during the event. The room code gives player access; it does not grant host control.

## Controls and scoring

- **Move:** A/D or left/right arrows.
- **Jump:** Space, W, or up arrow. Release before jumping again.
- **Chest powers:** JSON worlds use their authored power-chest roles. Forest and tide each use three authored power chests. The disabled legacy inferno course retains its chest definitions in source. Other chests can be decoys. Each chest randomly grants Sticky Boots (slow), Wrong Way (reversed controls), Ice Skates (slippery movement), or Ink Cloud (dark fog). You can use up to three powers per world, but hold/reserve only one at a time. At another chest, choose **Attack current** or **Replace with new** inside the world. Attack queues the held item and leaves the new chest unopened until the slot is free; Replace discards the held item and claims the new chest. Press **F** or **USE** to attack elsewhere. Unused powers and chest claims survive death and checkpoint rollback. Claimed reward chests disappear with a gold/cyan pixel burst; collected coins disappear with gold sparkles. Decoy chests remain. Replacing, dying, or using a power never regenerates a claimed chest. The unopened reward is stable if you walk away and return. An old unreserved item is discarded on entering the next world; a queued item survives and blocks pickup until consumed.
- **Targeted coin attacks:** Collect **30 coins** by default, then click **Attack [Q]** below the Power slot or press **Q**. Choose a power by clicking or pressing **1–4** (Sticky Boots, Wrong Way, Ice Skates, Ink Cloud), then choose one opponent. This does not need or consume a chest power. The collapsed Attack board has the same height as Total score; the chooser expands only when opened. The Attack board hides when you cannot afford it; while an attack waits or its questions are open, the same card shows its queue/in-progress status. Your cooldown starts when the selected defender answers or times out, alongside the result/effect. A wrong or unanswered attack starts the cooldown when it backfires instead. Each player has their own cooldown (default **one minute**); the host can configure both cost and cooldown in Game settings. Your spendable coins carry across worlds and deaths, while **your score never decreases when you spend them**. Refresh/rejoin resets the balance with your run. Coins are reserved when your request joins the queue and spent when its attack question begins, whether the attempt succeeds, backfires, times out or is blocked. A request canceled before it starts releases the coins without starting a cooldown. Only one of your coin attacks can wait in the queue at a time. Opponents may be in another world or respawning; disconnected and finished players cannot be selected, and a refreshed run cannot inherit an old attack.
- **Attack and defense:** A correct chest attack challenges **everyone else who is eligible**, across all worlds; a correct coin-funded attack challenges **only the selected opponent**. The attacker has one general-knowledge question; wrong or unanswered applies the power to themselves. After a correct attack, each targeted opponent gets a private defense question before the effect begins. Correct defenders block individually; incorrect or missing answers receive the effect together. Answers ignore case and extra whitespace; answer keys stay on the server. Defaults are 15 seconds to attack, 15 seconds to defend, and an 8-second effect. The host can set each duration independently to **1–60 seconds** in Game settings. Each question allows one attempt, and phases resolve early when everyone has answered. Defenders can move again as soon as their own answer is accepted, correct or incorrect, including host challenges. For both targeted coin attacks and global chest powers, the attacker stays frozen until all defenders answer or the defense deadline resolves. The attacker’s waiting-for-defenders card explains that movement is paused and resumes once all defenders answer or time runs out.
- **Host challenges:** During the race, the host can choose Sticky Boots, Wrong Way, Ice Skates, or Ink Cloud without a chest or attacker quiz. Every connected, spawned player who has not finished receives a private defense question, even while respawning. Correct answers block individually; wrong or missing answers receive the selected power. These challenges use the same queue, defense window, power strength, and effect duration as chest attacks. Targets are selected when the queued challenge begins. Host reconnection preserves queued challenges; ending/resetting the round clears them.
- **Power queue and display:** Only one power turn (attack, defense, then effect/result) runs across the room at a time. Other requests enter a FIFO queue with positions in the upper-left HUD. The result banner lasts the full configured effect duration, including a fully blocked result. Level-escape broadcasts use two-second slots in the same queue. Queued items survive death and level changes; disconnect/refresh cancels pending uses, and round end/reset clears all requests and effects. No available opponent means the held power is kept. The question and answer controls appear together inside the game viewport, including after tab/fullscreen changes. By default, Ink Cloud darkens its previous fog scene by a further **88%**, while HUDs, quizzes, and broadcasts remain readable. The host follows shared power phases on the broadcast stage.
- **Power strength settings:** Sticky Boots speed is 10–90% of normal (default 25%); Wrong Way speed is 50–200% while controls stay reversed (default 100%). Ice Skates now reach **170% of normal speed** by default, configurable from 110–250%, with braking grip from 2–50% (default 12%); lower grip makes you coast farther. Ink darkness is configurable from 0–95% (default 88% additional darkening). The server fixes strength when the power turn starts, and the affected browser applies those values locally.
- **Audio is enabled by default.** The supplied full WAV loops play for their respective lobby, forest, tides, and podium tilesets; the disabled inferno audio remains available in the repository. Reaching a stage exit banks your score, stops its loop, and plays that biome's victory stinger once. You stay safely at the exit until the stinger finishes, then enter the next world in the host's selected order. Attacks received during this transition keep their question and deadline while the next world loads. After the final stinger, podium music plays while you wait for the room timer. The shared timer keeps running; round expiry or manual end still sends everyone straight to the ceremony. The top-right speaker mutes or enables music and effects together. Hover over it, or focus it with the keyboard, to reveal a 0–100% volume slider; your chosen level is kept when toggling mute. Sound effects use the supplied universal WAV files in `public/assets/audio/sfx/` across every level, the lobby, and podium, regardless of theme. Music, victory cues and effects are volume-matched during playback, with bounded amplification and peak protection. Background music plays at 50% of the matched level; victory cues and effects retain their level. The original audio files stay unchanged.
- Playback starts on your first click or keypress, as required by browser autoplay rules. Audio pauses in a hidden tab and resumes when you return. Muted, hidden, or unavailable playback still allows the stage-clear pause to finish after the stinger's duration. Audio files load from this game's server; no extra dependencies are needed.

- Music, victory cues and sound effects now load lossless `.compressed.flac` copies, with automatic fallback to the original WAV if loading or decoding fails. All 35 original WAVs remain available. The copies preserve the same audio and durations while reducing total file size from 16.80 MB to 8.24 MB (51%).
- Touching a creature's body is safe. Projectile hits and active melee attack hits kill instantly, as do spikes, disguised traps, and falls. Jumping onto a creature from above still defeats it and bounces you upward. Creatures marked as flying remain in the air when their support platforms vanish. Death reveals disguised spikes or bombs and creates a pixel explosion.
- Legacy spike hitboxes are 15% smaller in width and height than their artwork, including disguised spikes. JSON levels use their authored hazard geometry. Light edge grazes are more forgiving; the inner spike area remains lethal.
- Platform widths, heights, gaps, and spacing vary deterministically by world. Critters patrol their assigned ground or raised platforms; authored creatures can follow a selected chain of adjoining platforms and chase players standing on that chain. Leaving it makes them resume patrol. Configured melee creatures repeat their attacks at close range, with damage only during their authored strike frames. Some enemies telegraph and fire aimed pixel flames at 120 pixels/second, with a 16×16 collision body and a 4.8-second firing interval (half the previous rate). Flames are lethal and expire after three seconds.
- JSON spawn and checkpoint banners default to a midpoint foot anchor, with authored custom anchors supported. The forest checkpoint at X=3125 uses this midpoint to land safely, and the hog beside the X=2120 checkpoint stays off its landing platform. JSON worlds use their authored checkpoint markers and respawn anchors; the disabled legacy inferno course retains **checkpoints at 25%, 50%, and 75%** in source. Pass each blue flag to save your location, points, collected coin IDs, and progress. Reached flags stay gold, and only a later flag replaces your save. Revisiting an earlier flag cannot downgrade or update that save. The 100% exit banks the completed world.
- Respawn after **3 seconds** at the checkpoint if reached, or at the current world’s start otherwise, with unlimited attempts. All collected coins and their points survive death immediately, including before the first checkpoint. Collected coins never reappear. Death rolls distance/progress back to the checkpoint, or to the world start before the first flag. Moving platforms and enemies restart their cycles.
- Each attempt earns coin points plus points for the farthest distance reached. Walking backward and collecting a coin twice cannot increase the score.
- Completing a world banks its full score once, including the checkpoint-protected points, then clears that checkpoint for the next world. Banked points survive all deaths. Coin points remain safe even before reaching a checkpoint.
- When time expires, the final total includes banked points and current attempt points. Highest score wins; equal scores favor the earlier full completion, measured from the room’s start. Remaining equal scores keep join order. Final rankings are frozen: leaving, reconnecting, or joining after time expires cannot change anyone’s podium place. New arrivals after the round watch as unranked spectators when the room has capacity.
- Clearing a world queues a broadcast inside everyone's game viewport. Broadcasts display one at a time, for two seconds each. Clearing the last world in the selected sequence banks the final score and waits for the shared timer, countdown, and podium teleport.
- **Refreshing in the same browser tab resumes your run while the room still exists.** Position, coins, checkpoints, banked score, inventory and remaining effects/cooldowns are preserved using a private player credential and a local tab save. The room timer and respawn deadlines continue while away. New rounds start fresh; server restarts clear rooms. Home/leave clears your recovery credential, and a fresh join without it starts a new run. If the local save is unavailable, the game shows a recovery error and lets you explicitly start over with the remaining time. Closing the tab or changing devices is not supported recovery. Use distinct player names. A disconnected player cannot continue moving; pending attacks still cancel on disconnect.
- Returning after Alt-Tab or a suspended browser resumes at normal world speed without replaying a backlog of missed physics. The shared room timer, power deadlines, and respawn deadlines still apply while away.
- Joining enters the playable lobby immediately; no Spawn click is required. While the room is in the lobby, edit your name or choose a circular avatar portrait and a color underneath it inside the game viewport. Changes apply live without resetting your position or score. Identity locks when the host starts the race and stays locked through results. A host reset returns connected players to a fresh, immediately playable lobby run; arrivals after published results remain unranked spectators.

## Deploy on Render

This is a **Node Web Service**, not a static site. HTTP and WebSockets share the same port. The browser uses `wss://` automatically on HTTPS.

1. Put this directory in a Git repository and push it to your Git provider.
2. In Render, create a **Blueprint** from the repository to use [render.yaml](render.yaml), or create a **Web Service** with:

   | Setting | Value |
   | --- | --- |
   | Runtime | Node |
   | Build command | `npm ci` |
   | Start command | `npm start` |
   | Health check | `/health` |
   | Node version | 22 or later |

3. Deploy and open the provided `https://…onrender.com` URL. Share that URL or the host’s invite link with the team.
4. Keep the service at **one instance**. Rooms live in server memory. Restarts, deployments, or instance replacement clear rooms and running games. Avoid changing deployments during a round.
5. Before game day, rehearse from two different internet connections: create a room, join, practice movement while changing name/avatar/color, launch a vote, start, die, check the host's score rollback and progress updates, use/defend a power, and finish/end the round. Include a full 25-player rehearsal.

Render’s official guides cover [Node services](https://render.com/docs/deploy-node-express-app), [port binding](https://render.com/docs/web-services#port-binding), and [WebSockets](https://render.com/docs/websocket).

Each player's browser runs its own physics, enemies, collisions, coins, checkpoints, deaths, score, and level transitions. Movement responds locally and does not wait for the network. The server deliberately trusts gameplay summaries for this casual game; it does not replay physics or prevent score tampering.

The server coordinates rooms, the shared timer, random chest rewards/inventory, the global power queue, private quizzes and answer validation, votes, broadcasts, and final results. Clients report compact totals at 5% progress milestones, coin collections (batched), checkpoints, deaths/respawns, world completion, chest contact, and the final cutoff. Detailed progress goes to the host; ordinary leaderboard changes are batched at most once per second and include only changed players and ranks. Your movement and local score remain immediate. Coin earnings send a private wallet update instead of a full room snapshot when no inventory change requires one. Joining or reconnecting still receives the complete roster, and final results publish through the existing settlement flow. Shared interaction events retain their existing timing. No movement inputs, world simulation snapshots, or CCTV views are transmitted. Incoming coordinator messages never replace local gameplay state.

Final gameplay totals represent the shared cutoff, including current unbanked points. The server collects final reports for at most two seconds, falls back to the last accepted totals when a player cannot report, and publishes immutable ranks. Completion tiebreakers use client-reported completion time relative to the room start, followed by join order. Refreshing during a run still resets it; finalization does not allow a new run to replace a pending result. See [the three migration milestones](docs/NETWORKING.md).

The original three-course pacing targeted a 5–10 minute casual session including surprise deaths; authored JSON courses need a fresh playthrough to assess duration. Actual completion time depends on player skill; a team rehearsal is the right place to tune obstacle spacing and round duration. Desktop keyboard play is supported. Mobile controls and persistent game recovery are outside this version.

## Artwork

Four avatars, enemies, hazards, coins, wildlife, and the goal flag use original generated sprites. Environment tiles and parallax scenery are drawn in canvas. See [the asset notes](docs/ASSETS.md) for the generation prompt and atlas mapping. The UI uses DM Sans and Space Grotesk from Google Fonts, with system fallbacks if those requests are unavailable.
